# 스크린 메일 번역기 (SMTranslator) v0.3.2

- **소스**: [github.com/armsone/SMTranslator-MacOS](https://github.com/armsone/SMTranslator-MacOS) (공개)
- **다운로드(DMG)**: [최신 릴리스](https://github.com/armsone/SMTranslator-MacOS/releases/latest)
  — Developer ID 서명 및 Apple 공증(notarization)을 거친 Apple Silicon(arm64) 전용 빌드입니다.
- **요구 사항**: macOS 15 이상, Apple Silicon(arm64) Mac. Intel(x86_64)은 지원하지 않습니다.

macOS 15 이상용 네이티브 앱입니다. 하나의 앱 안에 두 기능이 있습니다.

- **화면 번역**: 화면 위에 투명한 사각형 창 하나를 띄워 두고, 주 버튼을 누를 때마다 **한 번** 그 안을
  캡처해 텍스트를 인식(Vision OCR)하고 번역한 뒤, **번역문을 원문 줄이 있던 바로 그 위치에** 겹쳐 보여줍니다.
- **메일 번역**(0.2.0에서 기존 '메일 번역기'의 기능을 이 앱에 합침): Apple Mail에서 선택한 메시지를 읽어
  HTML 서식·표·이미지를 유지한 별도 결과 창에서 제목·본문·이미지 속 글자를 번역합니다.

캡처 이미지·인식 텍스트·메일 내용·번역 결과는 메모리에서만 다루며 디스크에 저장하지 않습니다.
기본 번역 방식(Mac 기본 번역)은 이 Mac 안에서 처리하며 외부로 보내지 않습니다. 외부 AI(ChatGPT·Claude·Gemini)를
직접 고르고 전송에 동의한 뒤 번역을 실행할 때만 **텍스트**가 해당 서비스로 전송됩니다(아래 [번역 방식](#번역-방식) 참고).

## 단축키 요약

| 동작 | 방법 |
|---|---|
| 화면 번역 창 보이기 | 전역 **⌃⌥⇧⌘T**, 메뉴 막대 › `화면 번역` |
| 새로 번역 / 원문보기 | 창의 `번역`↔`원문보기` 버튼, 메뉴 막대 주 항목, 창에 포커스가 있을 때 Return/키패드 Enter |
| 저장된 번역 ↔ 실제 화면 전환(다시 번역하지 않음) | 창에 포커스가 있을 때 Space (완료된 번역이 없으면 캡처·번역) |
| 화면 번역 창 숨기기 | Esc, ⓧ |
| 선택한 메일 번역 | 전역 **⌃⌥⇧⌘M**, 메뉴 막대 › `선택한 메일 번역`, Mail 위 `번역` 버튼, Mail › 서비스 › `메일 전체 번역`, 앱 활성 시 ⇧⌘T |
| .eml·이미지 파일 열기 | 앱 활성 시 ⌘O, 메일 번역 창으로 끌어놓기, Finder `다음으로 열기` |
| 설정(번역 방식·외부 AI 로그인·동의) | 앱 활성 시 ⌘, , 메뉴 막대 › `설정…` |

두 전역 단축키는 Carbon `RegisterEventHotKey`로 각각 따로 등록합니다(추가 권한 불필요). 하나가 다른 앱과 겹쳐
등록되지 않아도 다른 하나는 동작하며, 메뉴 막대 메뉴에 각각의 상태가 표시됩니다.

## 사용법

- **하나의 통합 창**: 흰색 둥근 테두리(약 12pt, 은은한 파란 글로우, 안/밖에 아주 얇은 0.6pt 검정 선을
  더해 밝은 배경에서도 윤곽이 보임)와 중립 회색 헤더(제목 스트립 + 툴바), 그리고 투명한 캡처 영역으로
  이루어집니다. 항상 위 고정은 기본으로 켜져 있습니다.
- **이동**: 헤더 맨 위 제목 스트립(전체 너비)이나 툴바의 빈 곳을 끌면 네이티브 창 이동(`performDrag(with:)`)으로
  움직입니다. 버튼·언어 선택은 그대로 동작합니다. 1pt라도 실제로 움직이는 순간(창이 움직이기 직전) 화면의
  번역을 즉시 숨기고(보관한 캡처·번역 해제는 다음 명시적 동작으로 미룸) 진행 중 작업을 취소하며, 그 뒤에는 `번역`을 다시 누를 때까지 영역 변경을 전혀 감지하지
  않습니다. 움직이지 않은 클릭은 결과를 그대로 둡니다.
- **크기 조절**: 좌/우 가장자리 전체(가로), 아래 가장자리(세로), 헤더 위쪽 얇은 띠(세로), 네 모서리(대각선).
  가장자리 안쪽 약 8pt까지가 조절 영역이며 알맞은 커서가 표시됩니다. 최소 크기는 툴바가 잘리지 않도록 제한됩니다.
  첫 실제 크기 변경 직전에 이동과 같은 방식으로 결과를 지우고 작업을 취소합니다.
- **창 크기 기억**: 사용자가 크기 조절을 마친 순간(마우스를 놓을 때)에만 창 크기를 `UserDefaults`
  (`ScreenOverlay.windowWidth`/`ScreenOverlay.windowHeight`, 글로우 여백 포함 pt)에 저장하고, 다음 실행 때 화면
  가운데에 그 크기로 엽니다. 숨겼다 다시 열면 위치·크기가 그대로입니다. 위치와 화면 내용(스크린샷·텍스트)은
  저장하지 않습니다. 실행 시나 디스플레이 구성이 바뀔 때 창이 현재 화면의 사용 가능 영역을 넘으면 그 안으로
  줄이거나 옮기며(최소 크기 이하로는 줄이지 않음), 이렇게 맞춘 크기는 저장값을 덮어쓰지 않습니다.
- **이동·크기 잠금**: 툴바의 `이동·크기 잠금` 토글을 켜면 이동과 크기 조절(아래 맞추기 포함)만 막히고 나머지 기능은 계속 동작합니다.
- **영역 맞추기**(메뉴 막대 › `영역 맞추기`): 창 **바깥 프레임**(글로우 여백 10pt 포함)을 대상에 맞춥니다. 실제
  캡처 영역은 그 안에서 헤더(약 58pt)와 테두리를 뺀 부분이라, 대상 창의 맨 위(제목 막대 등)는 헤더에 가려 캡처되지
  않습니다. 맞춘 뒤 번역을 자동으로 시작하지 않으며, 결과가 있었다면 이동과 같은 방식으로 한 번 지웁니다. 맞춘 크기는 한 번 저장됩니다.
  - `화면에 맞추기`: 포인터가 있는 화면의 메뉴 막대·Dock을 뺀 사용 가능 영역(`visibleFrame`) 전체. macOS 전체 화면 Space가 아닙니다.
  - `현재 창에 맞추기`: 이 창 캡처 영역 **가운데 아래**에 있는 다른 앱의 맨 위 일반 창, 없으면 가장 앞에 있는 다른 앱 창.
    후보가 없으면 창을 그대로 두고 경고음만 냅니다.
  - `맞추기 전 크기로`: 마지막 맞추기(메뉴·제목줄 더블클릭) 직전 위치·크기로 한 번 되돌립니다(메모리에만 기억).
  - **제목줄 더블클릭**: 제목 스트립이나 툴바 빈 곳을 더블클릭하면 `현재 창에 맞추기`와 같은 규칙으로 현재 뒤에 겹쳐진
    다른 앱 창의 크기·위치에 맞춥니다(이동·크기 잠금 중에는 동작하지 않습니다). 한 번 끌기(Shift 포함)는 항상 일반
    이동이며 창 목록을 조회하지 않고, 더블클릭할 때만 창 목록을 한 번 조회합니다.
  - 대상이 여러 화면에 걸치면 포인터(또는 창 가운데)가 있는 화면 하나의 사용 가능 영역으로 잘라 맞춥니다(캡처는 한 화면 안만 가능).
    툴바가 잘리지 않는 최소 크기(620×220pt)보다 작은 창에는 중심을 유지한 채 최소 크기로 맞추므로 대상보다 커질 수 있습니다.
- **주 버튼(제목 스트립 오른쪽) = Enter**: `번역` → 모든 줄의 번역이 성공하면 `원문보기`로 바뀝니다.
  `원문보기`를 누르면 번역 패치만 숨겨 투명한 캡처 영역 너머의 **실제 화면**(아래 앱의 지금 모습)을 그대로 보여주고
  버튼은 다시 `번역`이 됩니다. 캡처 이미지를 그리지 않으며 새로 캡처·인식·번역하지도 않습니다. 이때 캡처 영역은
  평소처럼 클릭이 아래 앱으로 통과합니다. 이때 `번역`(Enter)은 **새로 캡처·번역**합니다. 즉 Enter를 반복하면
  새 번역 → 실제 화면 → 새 번역 … 순서가 됩니다. Return·키패드 Enter·메뉴 막대 주 항목이 같은 동작입니다.
- **Space = 저장된 번역 전환**: 완료된 번역이 없으면 캡처·번역합니다. 완료된 번역이 있으면 다시 인식·번역하지 않고
  실제 화면 ↔ 보관한 **같은** 번역 패치를 즉시 오갑니다(외부 AI 요청·브라우저 전송도 새로 하지 않음).
  실제 화면을 보인 뒤에도 번역은 보관되어 다음 Space에 바로 돌아옵니다. 그 사이 아래 앱 내용이 스크롤 등으로 바뀌었다면
  돌아온 번역은 캡처 당시 위치 그대로라 맞지 않을 수 있으니 `번역`(Enter)으로 새로 번역하세요. 보관분은 창 이동·크기 변경, 언어·번역 방식
  변경, 새 캡처 때 버려지며, 이후에는 다시 `번역`을 눌러야 합니다.
- Space/Enter는 이 창이 앞(키 창)에 있을 때만 동작합니다. 언어·색상 팝오버, 외부 AI 브라우저, 메일 번역 창,
  글자 입력 칸에서는 가로채지 않습니다. 처리 중에는 둘 다 비활성화되며 Esc(숨기기·취소)만 동작합니다.
- **상태 표시**: `화면 캡처 중` → `텍스트 인식 중` → `번역 중 (완료줄/전체줄)` → `완료`.
  번역은 줄이 끝나는 순서대로 바로바로 원래 위치에 나타납니다(인위적 지연 없음).
  외부 AI 방식에서는 `제공사 · 단계 · 남은 시간 (완료줄/전체줄)`과 남은 시간 막대가 표시되고, 주 버튼이 `취소`가 됩니다.
- **원문 언어 `자동 인식`**(기본값) → **번역 언어**(기본 `한국어`): 일본어와 영어가 섞인 화면처럼 언어가 여러 개여도
  버튼 한 번으로 모두 번역 언어로 옮깁니다. 줄마다 따로 누를 필요가 없습니다. 번역 언어는 자동 선택 없이 직접 고릅니다.
  - OCR: Vision `automaticallyDetectsLanguage`를 켜고 우선순위 목록(일본어·영어·중국어 간체·한국어 중 이 기기가 지원하는 것만)을 넘깁니다.
  - 줄 단위 언어 판별(`NLLanguageRecognizer` + 문자 단서, 메모리에서만): 가나가 있으면 아주 짧아도 일본어, 한글이 있으면 한국어로 봅니다.
    짧은 영어 줄(메뉴·버튼 이름 등)은 화면의 우세 언어(예: 일본어)를 물려받지 않고, 같은 캡처의 확실한 라틴 문자 줄 언어나
    영어 쪽으로 약하게 기울인 단독 추정을 따릅니다. 한자만 있는 줄은 같은 캡처에 일본어만 있으면 일본어, 중국어만 있으면 중국어를
    따르고, 그렇지 않으면 단독 추정이 확실할 때만 정합니다. 한 줄 안을 단어별로 쪼개지 않습니다.
  - Apple 번역: 같은 언어 줄끼리 한 묶음으로 보내고(한 묶음에 여러 언어를 섞지 않음), 판별한 원문 언어를 명시합니다.
    언어를 정하지 못한 줄은 요청하지 않고 원문 그대로 둡니다. 언어 선택창을 띄우지 않으며 건너뛴 수를 표시합니다. 진행 표시는 전체 줄 기준이며
    묶음이 바뀌어도 처음부터 다시 세지 않습니다. 한 묶음이 실패해도 이미 받은 줄은 남고 나머지 묶음을 이어 번역하지만, 전체는
    `완료`가 아니라 `번역 오류 (k/N줄 완료)`로 표시합니다(다른 방식으로 자동 대체하지 않음).
  - 숫자·기호만 있는 줄과 이미 번역 언어(예: 한국어)인 줄은 번역 요청 없이 원문 그대로 둡니다.
  - 외부 AI: 요청 묶음·글자 수 상한·동의·실행당 요청 수는 같고, 요청문에 "항목마다 언어가 다를 수 있으니 항목별로 판별해
    번역 언어로 옮기라"고 지시합니다(추가 요청 없음).
  - 언어 판별은 완벽하지 않습니다. 아주 짧은 줄, 한자만 있는 줄, 한 줄 안에 여러 언어가 섞인 경우는 틀릴 수 있으며, 그럴 때는
    원문 언어를 직접 골라 고정하세요(직접 고르면 예전과 같이 OCR·번역 모두 그 언어로 고정).
  - 처음 쓰는 언어 조합(예: 일본어→한국어, 영어→한국어)은 그 언어 줄을 실제로 번역할 때 시스템이 모델 다운로드를 안내할 수 있습니다.
- **번역 방식 메뉴**(툴바의 `Mac 기본` 등): 메일 번역과 같은 방식을 함께 씁니다. 아래 [번역 방식](#번역-방식) 참고.
- **번역 패치**: 창 뒤 화면을 흐리게 비추는 네이티브 머티리얼 위에 배경색(기본은 원문 글자 뒤 배경에서
  자동 추출, 기본 진하기 95%)을 얹고, 그 배경 밝기에 맞춰 검정/흰색 중 더 잘 읽히는 글자색을 자동으로
  골라 불투명 고대비 번역문을 그립니다. 패치에는 별도 테두리 선이 없으며, 패치가 없는 캡처 영역은
  투명하며 클릭이 아래 앱으로 통과합니다.
- **번역문 색상 설정(🎨 팔레트 버튼)**: 툴바에서 팔레트 아이콘을 누르면 팝오버가 열립니다.
  - `자동 색상`(기본 켜짐): 캡처 이미지에서 각 원문 줄 바로 뒤 배경색을 추출해 그대로 배경으로 쓰고,
    글자색은 그 배경의 명도 대비로 검정/흰색 중 자동 선택합니다. 실제 픽셀 추출이 안 되는 줄(예: 캡처
    영역 경계에 걸친 경우)은 중립 회색(라이트 0.96/다크 0.12 명도)으로 안전하게 대체합니다.
  - `자동 색상`을 끄면 배경색·글자색 ColorPicker가 활성화되어 수동으로 고정 색을 고를 수 있습니다.
  - `진하기` 슬라이더(0~100%, 기본 95%)는 자동/수동 모드 모두에서 항상 동작하며 패치 배경의 불투명도만
    조절합니다(번역 글자 자체는 항상 완전 불투명).
  - 설정은 즉시 화면에 이미 표시된 번역문에도 다시 적용되고, `UserDefaults`에 저장되어 다음 실행에도
    유지됩니다. 원문보기 중에는 패치를 숨기고 실제 화면을 보이므로 색 설정이 보이지 않습니다.
  - 배경색 추출은 캡처당 한 번만 이미지를 디코딩하고 각 OCR 줄마다 한 번만 계산합니다(화면을 다시 그릴
    때마다 재계산하지 않음). 원문 글자 획을 배경으로 오인하지 않도록, 줄의 타이트한 인식 박스 내부는
    제외하고 그 바로 바깥 가장자리 픽셀만 샘플링해 채널별 중앙값을 씁니다. 캡처 이미지는 이전과 동일하게
    메모리에서만 다루며 디스크 저장이나 외부 전송을 하지 않습니다.
- **Esc / 제목 스트립의 ⓧ**: 창을 숨기고 진행 중 작업을 취소합니다. 앱은 계속 실행됩니다.
- **전역 단축키 ⌃⌥⇧⌘T**: 창을 보여주고 앱을 활성화합니다(Carbon `RegisterEventHotKey`, 추가 권한 불필요).
  다른 앱이 이미 사용 중이면 상태 줄과 메뉴에 안내가 표시됩니다.
- **메뉴 막대 아이콘**: `화면 번역`(창 보이기/숨기기), 번역/원문보기, `영역 맞추기` 하위 메뉴, `선택한 메일 번역`, 메일 번역 창 열기,
  번역 방식, 설정, `Dock에 아이콘 표시`, 정보, 종료가 바로 보이고, Mail 위 번역 버튼 표시·로그인 시 자동 시작·
  업데이트 확인·자동 업데이트는 `옵션` 하위 메뉴에, 두 단축키·로그인 항목·업데이트 상세 상태는 `앱 상태` 하위
  메뉴에 모아둡니다(문제가 있을 때는 상위 목록에 바로 안내가 뜹니다). 메뉴 막대 아이콘은 항상 떠 있습니다.
- **Dock에 아이콘 표시**(기본 꺼짐): 메뉴 막대 메뉴와 설정에 같은 항목이 있으며 둘 다 같은 값을 공유합니다. 꺼져 있으면
  메뉴 막대 아이콘만으로 앱을 쓰고 Dock에는 나타나지 않습니다. 켜면 Dock 아이콘이 나타나 Dock 아이콘 클릭으로도
  화면 번역 창을 다시 열 수 있습니다. 어느 쪽이든 단축키·Mail 연동·설정·창은 그대로 동작합니다.

## 메일 번역

- **선택한 메일 번역**: Apple Mail에서 메시지를 선택한 뒤 ⌃⌥⇧⌘M, 메뉴 막대 `선택한 메일 번역`, Mail 위 `번역` 버튼,
  또는 Mail › 서비스 › `메일 전체 번역`을 누릅니다. 이 앱 창을 앞으로 가져오기 **전에** Mail의 선택 메시지 원본을
  먼저 읽습니다. 여러 개가 선택되어 있으면 첫 번째만 번역하고 그 사실을 알립니다. Mail이 실행 중이 아니면 Mail을
  임의로 실행하지 않고 안내만 합니다.
- **결과 창(`메일 번역`)**: 원래 메일 번역기의 화면을 그대로 옮겼습니다.
  - HTML 메일은 원본 서식(표·색상·글꼴·이미지 배치)을 유지한 격리된 웹 보기에서 글자만 번역해 보여 줍니다.
    외부 요청 차단 규칙을 먼저 준비하고, 준비하지 못하면 읽기용 텍스트 보기로 대체합니다(`보기` › `HTML 메일 원본 서식 유지`).
  - 제목, 본문, 첨부·인라인 이미지 속 글자(Vision OCR)를 번역하고 이미지 위 제자리에 번역을 덧씁니다(원본 픽셀은 바꾸지 않음).
  - `보기`: 번역만 / 번역 + 원문 / 원문만, 이미지 번역 상세 목록, 인식 영역 번호(디버그), 창 항상 위.
  - 원본 언어(자동 감지 포함: 단위마다 언어별로 묶어 번역하며, 12자 미만 짧은 단위도 가나·한글은 그 언어로, 일본어처럼 다른 문자를 쓰는
    메일 속 짧은 영어 단위는 문서 언어를 물려받지 않음)·대상 언어 선택, `번역 복사`, `원격 이미지 불러오기`, `.eml/이미지 파일 열기`, 끌어놓기.
  - 도구 막대는 사용자 지정할 수 있습니다(도구 막대에서 Control-클릭 › 사용자화).
  - Mail에서 직접 요청한 메시지의 원격 이미지는 HTTPS 주소만 쿠키·캐시 없이 메모리로 한 번 불러옵니다(이미지 서버에
    IP 주소와 열람 시각이 전달될 수 있음). 파일로 연 메일은 확인을 받은 뒤에만 불러옵니다.
  - 새 요청·언어/방식 변경·창 닫기 시 진행 중인 작업과 늦게 도착한 이전 결과는 세대 번호로 버립니다.
- **창을 닫으면** 메일 내용(문서·이미지·번역·진행 중인 외부 AI 실행)을 메모리에서 지웁니다. 앱은 계속 실행됩니다.
- **Mail 위 번역 버튼**(기본 켜짐): Mail이 앞에 있을 때 별도 작은 `번역` 버튼을 띄웁니다. 손잡이나 버튼을 끌어
  위치를 옮길 수 있고 위치는 기억됩니다. 손쉬운 사용 권한이 이미 있으면 Mail 도구막대 빈 공간을 따라가고, 없으면
  수동 위치에 표시합니다(이 버튼은 권한을 요청하거나 설정을 바꾸지 않음). Mail의 정식 도구막대 항목은 아닙니다.
  설정이나 메뉴 막대에서 끌 수 있습니다.
- 이전 독립 앱의 'Mail과 함께 실행'(LaunchAgent 보조 프로그램)은 옮기지 않았습니다. 이 앱의 로그인 시 자동 시작과
  메뉴 막대 상주가 그 역할을 합니다.

## 번역 방식

화면 번역과 메일 번역이 **하나의 선택**을 함께 씁니다(툴바, 메일 창 도구 막대, 메뉴 막대 › 번역 방식, 설정).
고른 방식은 다음 실행에도 유지됩니다. 실패해도 다른 방식으로 **자동 대체하지 않습니다**.

| 방식 | 처리 위치 | 비고 |
|---|---|---|
| **Mac 기본 번역**(기본값) | 이 Mac | Apple Translation. macOS 26.4 이상에서는 `lowLatency` 전략, 그보다 낮은 macOS에서는 기존 기본 구성 |
| Apple Intelligence 우선 | 이 Mac | macOS 26.4 이상에서만 선택 가능(`highFidelity`). 사용할 수 없으면 시스템이 기본 번역으로 처리하며, 실제 사용 모델은 앱에서 확인할 수 없음 |
| ChatGPT / Claude / Gemini | 외부 웹 서비스 | API 키 없이, 설정에서 직접 로그인한 공식 웹 계정 세션 사용 |

- 화면 번역의 Apple 방식은 여러 줄을 한 번에 스트리밍 배치로 번역해 끝나는 줄부터 바로 그립니다
  (원문 `자동 인식`이면 언어별 묶음마다 차례로).
- 외부 AI 방식의 화면 번역은 인식한 **줄 텍스트만** 큰 묶음(최대 150줄·9,000자, 줄마다 따로 보내지 않음)으로 보내고,
  응답의 항목 ID를 각 줄 위치에 대응시켜 그립니다. **스크린샷 이미지와 위치 정보는 보내지 않습니다.**
  응답은 요청한 ID만 허용하는 엄격한 형식 검증을 거치며, 모든 줄이 들어와야 `완료`·`원문보기`가 됩니다.
  누락된 줄은 같은 제공사에 한 번만 다시 요청하고, 형식 오류 1회·Gemini 일시 오류 1회만 자동 재요청합니다
  (메일 번역과 같은 규칙, 한 번 실행에 최대 4회 요청).
- 외부 AI 방식의 메일 번역은 제목·본문 텍스트·이미지 OCR 텍스트만 보냅니다(원본 HTML·이미지 파일·주소 헤더 제외).
- **방식·언어를 고르거나 파일을 여는 것만으로는 아무것도 보내지 않습니다.** 화면 번역은 `번역`을 누를 때,
  메일 번역은 선택한 메일 번역을 요청하거나 결과 창의 번역 실행 버튼을 누를 때만 보냅니다.
- 제공사별로 처음 실행할 때 메일·화면 번역 전송 범위를 모두 설명하는 동의를 받습니다. 이 앱의 동의만 쓰며
  이전 독립 메일 번역기의 동의·로그인 쿠키는 가져오지 않습니다. 설정에서 동의를 철회할 수 있습니다.
- 기본적으로 AI 브라우저는 숨긴 채(창 안의 불투명 덮개 아래 실제 크기 웹 보기) 진행하고 단계·남은 시간(1:59부터)·취소를
  표시합니다. 로그인·보안 확인이 필요하거나 자동 입력이 맞지 않을 때만 보이는 브라우저로 전환하며, 그때는
  `요청 복사`/`응답 적용`으로 수동 진행할 수 있습니다(같은 검증 적용). 설정의 `AI 브라우저 항상 보기`로 처음부터 볼 수 있습니다.
- 외부 AI로 보낸 내용은 해당 서비스의 대화 기록에 남을 수 있으며 그 서비스의 정책이 적용됩니다.
- 설정 › 외부 AI: 로그인 상태(확인 중/로그인됨/로그인 필요/확인 안 됨), 로그인 창, 상태 다시 확인, 브라우저 표시 방식,
  동의 철회, 외부 AI 로그인 세션 모두 지우기, 최근 진단 로그 공유(단계 이름·시간·개수만, 내용·주소·계정 없음).

### 결과가 지워지거나 유지되는 경우

- 자동/주기 캡처는 없습니다. 실행·언어 변경·영역 변경 시에도 자동으로 다시 캡처하지 않습니다.
- 창을 이동하거나 크기를 바꾸면 기존 결과(캡처·번역 보관분)는 아래 화면과 맞지 않으므로 지워지고, 진행 중 작업은
  취소됩니다. 명시적 번역(버튼·Enter·결과가 없을 때의 Space·메뉴)이 그 영역에 대한 1회용 감지를 켜고, 첫 실제
  이동/크기 변경 직전에 한 번만 지운 뒤 감지를 끕니다(`didMove` 관찰·폴링 없음). 늦게 도착한 캡처·인식·번역
  결과는 세대 번호로 버려지며 마우스를 놓아도 다시 그리지 않습니다. 상태 문구 변경·결과 뷰 해제·외부 AI 정리는 다음 번역 등 명시적 동작까지 보류합니다. 움직이지 않은 클릭이면 결과를 그대로 둡니다.
- 언어나 번역 방식을 바꾸면 진행 중 작업을 취소하고 보관한 결과도 지웁니다(Space로 옛 번역이 다시 보이지 않게).
- 창을 숨기면 진행 중 작업만 취소됩니다(이미 받은 줄은 남지만 `완료`로 표시하지 않음).
- 인식된 글자가 없거나 캡처/번역이 실패하면 `원문보기`로 바뀌지 않습니다. 스트리밍 중 오류가 나면
  받은 줄은 남기고 `번역 오류 (k/N줄 완료): …`를 표시하며 버튼은 `번역`(재시도)입니다.

## 권한

- **화면 기록**: 실행 시 요청하지 않습니다. `번역`을 눌러 캡처가 시작될 때 `CGPreflightScreenCaptureAccess`로 먼저 확인하고,
  미승인이면 실행당 최대 1회만 `CGRequestScreenCaptureAccess`를 호출합니다. 거부 상태면 설정 위치를 안내합니다.
- **번역 모델**: 처음 쓰는 언어 조합이면 첫 캡처 때 시스템이 다운로드를 안내할 수 있습니다(필요할 때만, 실행 시 미리 받지 않음).
  같은 언어 조합에서는 세션 구성이 유지되어 캡처마다 다시 만들지 않습니다. 원문 `자동 인식`은 원문 언어를 미리 알 수 없으므로
  캡처 전에 가용성을 확인하지 않고, 화면에서 실제로 감지한 언어를 번역할 때 그 언어 조합만 안내됩니다.
- **Mail 자동화(Apple Events)**: 선택한 메일 번역을 실행할 때만 Mail의 선택 메시지 원본을 읽기 위해 사용합니다.
  처음 실행 시 macOS가 `Mail 제어` 허용 여부를 한 번 묻습니다(허용은 사용자의 선택이며 앱이 반복해서 묻거나 설정을
  바꾸지 않음). 거부했다면 시스템 설정 › 개인정보 보호 및 보안 › 자동화 › 스크린 메일 번역기 › Mail에서 직접 허용하거나
  `.eml 파일 열기`를 쓸 수 있습니다. 앱은 `com.apple.security.automation.apple-events` 권한 항목만 추가로 가지며
  Hardened Runtime과 라이브러리 검증은 그대로입니다.
- **손쉬운 사용**: 요청하지 않습니다(`AXIsProcessTrusted`로 확인만 하며 권한 요청 대화상자를 띄우는 호출은 쓰지 않음).
  이미 허용돼 있으면 Mail 위 번역 버튼이 도구막대 위치를 따라갈 때만 창·도구막대 위치·크기를 읽습니다.
  권한이 없으면 이 기능도 권한 없이 쓰는 방식으로 동작합니다.
- **다른 앱 창 경계(영역 맞추기)**: `현재 창에 맞추기`를 고를 때와 제목줄을 더블클릭할 때 **한 번만** CoreGraphics
  `CGWindowListCopyWindowInfo`(화면에 보이는 창만, 데스크톱 요소 제외)로 창 번호·소유 프로세스 번호·레이어·투명도·경계만 읽습니다.
  창 제목과 앱 이름은 읽지 않고, 결과는 그 동작이 끝나면 버리며 저장·기록·전송하지 않습니다. 스크린샷을 찍지 않고 새 권한을 요청하지
  않습니다. 이 앱 자신의 창, 메뉴 막대·Dock·떠 있는 패널 같은 일반이 아닌 레이어, 완전히 투명하거나 아주 작은 창은 제외합니다.
  창 경계는 주 디스플레이(`CGMainDisplayID`) 왼쪽 위 기준이라, 그 디스플레이의 `NSScreen` 높이로 AppKit 좌표로 바꿉니다.
- 번들 ID `com.local.screentranslator`와 Developer ID(팀 T7B4EPLHPK) 서명을 유지해 권한 기록이 이어지도록 했습니다.

## 로그인 시 자동 시작

`SMAppService.mainApp`을 사용합니다(LaunchAgent 파일 없음). `/Applications`에 설치된 앱에서만 동작하며,
최초 실행 시 1회 기본 등록합니다. 이후에는 메뉴에서 사용자가 바꿀 때만 등록/해제하고, 꺼 둔 선택은
재실행해도 존중합니다. 상태가 `승인 필요`이면 시스템 설정 > 일반 > 로그인 항목에서 직접 허용해야 하며,
메뉴에 실제 상태(켜짐/승인 필요/꺼짐)가 표시됩니다.

## 자동 업데이트 (Sparkle 2.10.0)

- 표준 `SPUStandardUpdaterController` 사용. 기본값: `SUEnableAutomaticChecks=YES`, `SUAutomaticallyUpdate=YES`,
  `SUVerifyUpdateBeforeExtraction=YES`, 시스템 프로파일링 끔. 메뉴에서 자동 업데이트를 끌 수 있습니다.
- 피드: `update-config.env`의 `SPARKLE_FEED_URL`
  (`https://github.com/armsone/SMTranslator-MacOS/releases/latest/download/appcast.xml`).
- 빌드 시 `Resources/UpdatePublicKey.txt`(EdDSA **공개키**)를 `SUPublicEDKey`로 넣습니다. 공개키나 HTTPS 피드가 없으면
  업데이터를 시작하지 않고 메뉴에 이유를 표시합니다. 개인키는 저장소에 없으며 로그인 키체인에만 있습니다.
- 피드가 아직 게시되지 않았거나(404 등) 받을 수 없으면 `업데이트 없음`이 아니라 Sparkle 오류로 표시됩니다.
- [SMTranslator-MacOS](https://github.com/armsone/SMTranslator-MacOS/releases/latest) 저장소(소스·릴리스·피드 통합)에
  공개된 최신 버전은 v0.3.2(이 문서의 버전: 화면 번역 UI 정리, 원문보기 = 실제 화면,
  창·읽기 영역 맞추기, 원문 자동 인식 및 미판별 글 건너뛰기)입니다.
  자동 업데이트의 실제 버전 교체 동작은 아직 사용자 확인 전이며, 검증되었다고 단정하지 않습니다.

### 업데이트 배포 절차 (TM)

1. `Info.plist`의 `CFBundleVersion`/`CFBundleShortVersionString`을 올립니다.
2. `scripts/package-update.sh` 실행 (선택: `NOTARY_PROFILE=<notarytool 프로필>`로 공증·staple).
   - 서명 키 계정은 `Resources/UpdateSigningAccount.txt`(또는 `SPARKLE_KEYCHAIN_ACCOUNT`)에서 읽으며,
     `generate_appcast --account`가 키체인에서 직접 서명합니다. 키를 내보내거나 출력하지 않습니다.
   - 기존에 등록해 둔 notarytool 프로필이 있으면 `NOTARY_PROFILE=ccmb-notary scripts/package-update.sh`로
     그대로 재사용할 수 있습니다(프로필 이름만 지정하는 것이며 별도의 비밀 값을 노출하지 않습니다).
3. `build/release/v<버전>/`의 DMG와 `appcast.xml`을 업데이트 저장소 릴리스 `v<버전>` 자산으로 올리고
   그 릴리스를 latest로 지정합니다.

## 빌드

요구 사항: Xcode 커맨드라인 도구, macOS 15 이상 SDK, 키체인의 Developer ID Application 인증서.

```bash
./build.sh            # → build/SMTranslator.app
```

`build.sh`가 하는 일:
1. `Vendor/Sparkle`이 없으면 `scripts/bootstrap-sparkle.sh`로 고정 URL의 Sparkle 2.10.0을 받아 SHA256 검증 후 풉니다
   (`SPARKLE_TARBALL=<로컬 tar.xz>`로 오프라인 사용 가능).
2. `Resources/AppIcon-source.png`가 바뀌었으면 `scripts/make-icon.sh`(sips + iconutil)로 `Resources/AppIcon.icns` 생성.
3. `swiftc`로 컴파일(`-F Vendor/Sparkle -framework Sparkle`, rpath `@executable_path/../Frameworks`).
4. Info.plist·아이콘 복사, Sparkle.framework를 `ditto`로 심볼릭 링크 보존 복사, 피드 URL·공개키 주입.
5. 외부 AI 공통 런타임·제공사 레지스트리(`Resources/aibi-browser-runtime.js`, `Resources/aibi-providers.json`, AIBI 0.5.3)를
   `Contents/Resources`에 복사.
6. Sparkle 내부(XPC → Autoupdate → Updater.app → 프레임워크) 후 앱 순으로 Developer ID + Hardened Runtime 서명
   (앱 본체에는 `Resources/SMTranslator.entitlements`의 Apple Events 항목만), `codesign --verify --deep --strict` 확인.

의존성 정보와 라이선스: `ThirdParty/DEPENDENCIES.md`, `ThirdParty/Sparkle-LICENSE`.

## 제한 사항

- 캡처 영역은 하나의 디스플레이 안에 있어야 합니다.
- 세로쓰기 텍스트는 특별히 처리하지 않습니다(위→아래 줄 순서).
- 원문 `자동 인식`의 언어 판별은 줄(문단) 단위 추정이라 아주 짧은 줄·한자만 있는 줄·한 줄 안의 여러 언어는 틀릴 수 있습니다.
  여러 언어가 섞인 화면에서 실제 번역 품질과 속도는 아직 측정하지 않았습니다.
- 번역문이 원문보다 훨씬 길면 최소 글꼴 크기에서 잘릴 수 있습니다.
- 메일 번역: 이미지가 아닌 첨부 파일은 열거나 번역하지 않습니다(첨부된 .eml은 본문에 펼침). 일부 인라인 서식·CSS 배경
  이미지·복잡한 이미지 글자 배치는 원본과 다를 수 있습니다. 외부 AI 한 번 요청 상한(9,000자)을 넘는 단락은 보내지 않습니다.
- 외부 AI 자동 입력은 제공사 웹 화면 변화에 영향을 받을 수 있습니다. 이 경우 보이는 브라우저의 수동 진행을 씁니다.
- 진단 로그(비밀 정보 없음: 버전, 경로, 로그인 항목/단축키/업데이터 상태, 번역 방식 이름): `~/Library/Logs/ScreenTranslator/diagnostics.log`.
  외부 AI 진단(단계 이름·시간·개수만): `~/Library/Application Support/com.local.screentranslator/AIBIDiagnostics/`.
